The foundation before the rewrite

Lasero is a Windows desktop application for designing and running laser engraving and cutting jobs on GRBL machines. This page is the visual and component foundation for it: one interaction colour, one geometry language, one icon family, every state drawn before any of it is implemented.

Specimens are rendered at the product's real values and real pixel sizes, so they can be measured rather than approximated. The page around them is deliberately a different world — graphite, IBM Plex, monospaced dimensions — so there is never a question about which pixels are the product.

Nothing here changes machine behaviour. Start, Pause, Stop, Frame, Home, Origin, Jog, Reset and Unlock appear only as visual states. Their semantics, the serial layer, firmware commands and machine coordinates are untouched, and a control rendering correctly is never a reason to enable it.

Type

Inter · bundled · 10 styles

Inter ships inside the application as a <Resource>. It is not a Windows font, so a family-name reference alone falls back to Segoe without saying so — always go through Font.Ui, Font.Display or Font.Numeric. Nothing below 12px anywhere. Four steps carry the whole product as Size.Text.Title / Section / Body / Meta, and markup carrying a literal FontSize now fails a test. Engineering values use Inter's tabular figures, never a monospace: fixed pitch made the inspector read like console output.

Spacing & radius

6 steps · 4 radii

Six spacing steps and no seventh. 32px is the largest gap anywhere in the product — compact but breathable, professional desktop density rather than SaaS whitespace. One geometry language: equivalent controls share one radius, and pill geometry is reserved for things that genuinely are chips. The 4px step exists because a 6px radius on an 18px swatch reads as a circle.

Icons

64 glyphs · one family

LASERO Precision Outline. Base geometries are Lucide on a shared 24×24 grid; the rest are drawn to the same grid, 1.75px stroke, round cap and join, single inherited colour. Sizes come from Size.Icon.Chrome / Sm / Md / Lg / Xl and markup carrying a numeric size fails a test — the product used to render icons at fourteen distinct sizes, with Glyph.Close alone appearing at three of them in the same dismiss role. The base set below is the geometry that actually ships in Lasero.App/Theme/Icons.xaml, extracted verbatim, so the drawing and the code cannot drift.

One family, five rendered sizes

Base set — ported from the shipping theme

New — drawn for Lasero

  • Engrave and Cut are a deliberate pair. Same plate, same beam: nicked in one, severed in the other. The contrast is the whole metaphor, and it survives at 16px.
  • The three processing modes are one systematic trio. Outline, outline plus hatch, nested outlines plus hatch — so Čára, Výplň and Výplň + čára read as steps rather than three unrelated pictures.
  • No second family, ever. The existing set was already coherent, which is why it was reused rather than replaced. Icons drawn inline as <Path Data= inside a view are how fragmentation starts.

Buttons

4 kinds × 6 states

One height (36px), one radius (8px), one icon gap (8px), one label style. Kind carries emphasis; state carries feedback. Focus is always a 2px cobalt ring — outside the fill on filled buttons with a surface-coloured gap, and replacing the border on unfilled ones.

Hover and press are one mechanic at two strengths: an ink wash over whatever the control already is, 6% and 14%. A per-kind pressed colour would be a second implementation of the same state, and every new button kind would have to re-derive it. The wash works on a cobalt fill, a red fill, a white surface and a transparent ghost alike.

Machine actions

Reference · 3 phases

Emphasis follows consequence. Starting work is the one 44px primary action; framing is secondary because it is rehearsal; stopping is destructive but never dominant, because a control that shouts at rest has nothing left when it matters. The phase decides which controls exist at all — a Start button does not sit disabled beside a running job.

  • Phase, not disabled state. Start exists when a job can start. Pause and Stop exist when one is running. Unlock exists when the controller is locked. Rendering all of them greyed out teaches nobody anything.
  • Destructive is distinct, not loud. Red fill and an explicit verb. No red panels, no red glow, no icon-only stop.

Startup

Reference

Neutral ground, the supplied wordmark, one thin indeterminate line. No illustration, no glow, no percentage — and no artificial delay: the window exists for exactly as long as loading takes, and if loading is instant nobody ever sees it.

Code deltas

Handoff · 7 closed · 1 open · 1 withdrawn

Where the shipping application currently disagrees with the system above. Recorded so they get closed during implementation rather than rediscovered, and so nobody mistakes a leftover for a decision. Three closed by correcting the system instead of the code, and one was withdrawn outright — the app was right and this page was wrong.

WhereDelta
Literal radii11 / 14 / 17 / 18 turned out to be circles and pills rather than drift, and they had no token. Radius.Pill (999, which WPF clamps to half the smaller side) now covers all of them plus the toggle thumb, which had been a circle expressed as Radius.Md and would have deformed the moment Md changed.
Type scale59 literals tokenised, 12 redundant style overrides deleted, and a test now fails on any literal FontSize in markup. DeviceSettingsWindow had been rendering its window title at 18 while its own section headings sat at 22 — the hierarchy was upside down. Page titles came down from 28 to 22, panel headers from 16 to 15, and inspector section headers from 15 to 13.
Shadow.PanelSplit into Shadow.Sheet / Tooltip / Dropdown / Modal. The canvas sheet, a modal and two popups had been sharing one 0.32-opacity, 34px-blur shadow whose own comment claimed exactly one surface used it.
Duplicate brushesBrush.BrandRed, Brush.PrimaryAction, Brush.PrimaryActionHover, Brush.OnPrimaryAction and Brush.AccentMuted removed. Brush.Info stays: it shares the accent value but names a genuinely different role.
Dropdown hoverComboBoxItem wore the cobalt selection tint on IsHighlighted, so hovering a dropdown looked like having already picked something. Hover is now the neutral wash and IsSelected carries the tint.
Inline iconsNot a real finding. IconGlyph is the renderer and its <Path> is bound to a Geometry; BitmapTraceWindow draws the traced bitmap outline, which is content rather than an icon. Neither hardcodes a glyph.
Icon sizes262 size attributes tokenised onto Size.Icon.Chrome / Sm / Md / Lg / Xl. The product had been rendering icons at fourteen distinct sizes. The renderer stroke also moved from 1.8 to 1.75 so the shipped icons finally match the exported SVG assets.
Pressed tokensWithdrawn. The app already separates press from hover by wash strength, so color/primary/pressed and color/destructive/pressed would have introduced a competing mechanic for one state. The values stay documented; nothing binds to them.
Bitmap re-editRaster settings can only be set at import. Reopening them non-destructively is still missing, so the workflow is delete and re-import.
