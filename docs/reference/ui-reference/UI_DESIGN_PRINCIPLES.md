# Lasero UI Design Principles

## Product character
Lasero should feel precise, calm, fast, trustworthy, modern, intentional, technically capable, and visually restrained.

## Visual hierarchy
Prefer hierarchy through spacing, typography, contrast, grouping, and alignment. Avoid using borders, shadows, cards, gradients, and accent color everywhere at once.

## Density
Lasero is desktop production software, not a marketing website. Prefer compact controls and efficient use of space.

## Cards and surfaces
Use cards only when they communicate real grouping. Avoid nested card-on-card layouts.

## Rounded corners
Use existing Lasero radius tokens. Pills belong mainly to tags, filters, compact suggestions, and status indicators.

## Color
Use the existing Lasero palette and accent color. Color should communicate selection, focus, status, and hierarchy.

## Typography
Keep hierarchy simple and consistent. Use bold for hierarchy, not decoration.

## Icons
Use the existing Lasero icon system. Avoid mixing random icon packs and generic “AI robot” imagery.

## Motion
Motion should explain change: state transitions, disclosure, feedback, and progress. Do not animate just to look “AI”.

## Inputs
Inputs must clearly communicate label, value, units, editable state, focus, validation, and disabled state.

## Toolbars
Use stable positions, predictable grouping, tooltips, active-state feedback, and keyboard shortcuts where appropriate.

## Inspectors
Use consistent row height, aligned labels/values, predictable grouping, and compact spacing.

## Empty states
Use a short explanation, one clear next action, and a few contextual suggestions if useful. Avoid giant artwork and marketing copy.

## Loading / progress
Prefer local progress feedback near the triggering action. Explain long-running work.

## Errors
Make errors specific, actionable, local, and retryable. Put technical details behind “Details”.

## Destructive actions
Prefer reversible actions and reliable undo over excessive confirmation dialogs.

## Selection and focus
Selection, hover, and keyboard focus must be visually distinct.

## Professional interaction standard
For each control ask: can the user predict what will happen?
For destructive actions ask: can the user recover?
For complex interactions ask: is there immediate feedback?

## Reference philosophy
Use Linear, Figma, Claude, ChatGPT, Raycast, Notion, and LightBurn as interaction-quality references. Do not clone their visual identity.

## Final quality test
A successful UI change should feel like it was always part of Lasero. If it looks copied from a component site, it is not finished.
