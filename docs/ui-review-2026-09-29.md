## P1

### P1-1 KAMIL: Minimize and Close are the same action, and the spec'd distinct Close is gone
- Screenshot: `e04-header-crop.png` (header crop), `e03-expanded.png`
- Element: Expanded header, buttons "+" (Nová konverzace), "−" (Zmenšit asistenta), "×" (Skrýt asistenta), `KamilAssistantHost.xaml` lines 285-312.
- Finding: "−" and "×" both bind `MinimizeCommand`. Both are 28x28 muted ghost glyphs about 10px, no label, no hover colour difference visible at rest. An "×" that does not close is a false affordance, and HANDOFF §2.1 says Close must be `Button.ChromeClose` (red hover) and lead to Hidden. The in-file comment says this was reversed on purpose ("misrepresented this action"), so this is a spec conflict to decide, not a slip.
- Fix (pick one and record it in HANDOFF §2.1):
  - A: keep one button. Delete the "×" block (lines 300-312), keep "−" with tooltip "Zmenšit na odznak · Esc". Removes the ambiguity, matches "avatar is the permanent anchor" (the panel cannot be closed, only minimized).
  - B: restore the spec. "×" uses `Button.ChromeClose`, command `HideCommand`/Hidden, gap 8px stays, reopen through the nav rail "Lasero Chat" (`OnLaseroChatClick`).
- Hover state could not be captured (see P3-5), so the resting-state finding is what is verified.

### P1-2 Machine panel: compatibility combo shows a raw record dump
- Screenshot: `i00-machine.png` (row under "Model a stav kompatibility")
- Element: `MachinePanelView.xaml:127`, ComboBox bound to `Connection.CompatibilityOptions`. Displays `MachineCompatibility { Id = existing-grbl, Display...` truncated at the field edge.
- Finding: `DisplayMemberPath="DisplayName"` is set but the selection box still renders `ToString()` of the record. Likely `DisplayName` is not a property of the item type (or the item type differs from the dropdown item), or `SelectedItem` is a different instance/type than the items. English identifiers leak into a Czech UI and the value is unreadable.
- Fix: verify `CompatibilityOptions` element type has a `DisplayName` property; if it is a record wrapper, add `public override string ToString() => DisplayName;` to `MachineCompatibility` (Lasero.Core) and add a unit test in `Lasero.Tests` asserting no option `ToString()` starts with "MachineCompatibility". Also give the ComboBox an `ItemTemplate` with `TextTrimming="CharacterEllipsis"` so a long model name never clips mid-word.

### P2-3 KAMIL Esc is unreliable
- Screenshot: `f00-after-esc.png` (no effect), `h01-after-esc.png` (no effect), `h02-after-esc2.png` (worked)
- Element: `KamilAssistantHost.OnPreviewKeyDown` (`.xaml.cs:758-765`)
- Finding: Esc minimized only on the third attempt (after clicking into the composer and sending two Esc). The first two attempts (focus on avatar after UIA invoke; focus in composer after a click) did nothing. The handler only fires when keyboard focus is inside the host (by design), so anything that puts focus elsewhere (canvas click, machine panel) makes Esc silently dead while the panel stays open. Part of this may be `keypress.ps1` foreground timing, so retest by hand.
- Fix: handle Esc at the window level when State is not Minimized/Hidden and no popup/text-edit owns Esc: `MainWindow.xaml.cs` `PreviewKeyDown` → `Kamil.StepBack()`, guarded by `!(Keyboard.FocusedElement is TextBox { IsKeyboardFocused: true } && canvas text edit active)`. Add the guard as a small pure function in `KamilAssistantViewModel` for a unit test.

### P2-4 Machine panel: disconnected state shows numeric telemetry as live values
- Screenshot: `i00-machine.png`, `i01c.png`
- Element: telemetry strip, `MachinePanelView.xaml:95-99` (`X mm 0.00, Y mm 0.00, Z mm 0.00, F 0, S 0`)
- Finding: no stale values from a previous connection and no alarm banner (pass), but the zeros are indistinguishable from a real machine at work origin. A user could read X 0.00 as "at home".
- Fix: add a `DataTrigger` on `Connection.IsConnected=False` setting `Text` to "–" (or `Opacity` 0.45) for the five `TelemetryValue` blocks; token `Brush.TextDisabled`. Keep the 0.00 format when connected.

### P2-5 Machine panel: informational banners use danger styling
- Screenshot: `i00-machine.png` (banner "Bezpečný simulátor — neotevře fyzický port ani laser."), `i03c.png` (banner "Pro přesné polohování ...")
- Element: `MachinePanelView.xaml` info banner near the serial port block and hint at line 279 (red border, red-tinted surface, red circled "i").
- Finding: red is reserved for destructive and error (DESIGN.md colour rules). Both messages are neutral guidance. Red at rest on a disconnected panel trains users to ignore real warnings.
- Fix: use `Brush.InfoMuted` surface + `Brush.SelectedBorder` border (info panel tokens) for both, keep `Brush.Danger` for actual alarm/error only.
